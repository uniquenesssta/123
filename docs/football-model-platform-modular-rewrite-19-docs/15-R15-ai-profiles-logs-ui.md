# R15：AI Workspace、OpenAI Profiles 与 Logs UI 重写——独立执行任务书

> 文档编号：`R15`  
> 前置阶段：`R14`  
> 后续阶段：`R16`  
> 本文档是唯一执行依据之一；必须与 `00-总体架构与前23节.md` 同时适用。

## 1. 阶段目标

- 完成 AI 会话、消息、输入、请求取消、上下文、OpenAI 配置和日志问题中心的模块化 UI。

## 2. 本阶段解决的实际问题

- 会话、草稿、请求、取消、配置、凭据和日志若混在一个页面会造成状态串线和敏感信息泄漏。

## 3. 前置输入与进入条件

- R14 完成。
- R9 后端协议和安全测试通过。

## 4. 明确范围

### 4.1 纳入范围

- Session Directory、Conversation、Composer、Pending Request、Cancellation、Context Picker、Profile Directory/Editor、API Example Parser、Credential Actions、Profile Test、Logs、Diagnostics Bridge。

### 4.2 排除范围

- 协议扩展。
- 正式研究后端。

## 5. 当前实现来源与扫描重点

- 旧 AI workspace/OpenAI profile/log pages。
- `src/api/client.ts` 的相关方法。
- `src/main.ts` 中会话、草稿、请求和日志状态。

## 6. 目标目录总览

```text
src/features/ai-workspace/
src/features/openai-profiles/
src/features/logs/
```

## 7. 目录与文件边界规则

- Conversation 只展示消息。
- Composer 只拥有草稿与发送意图。
- Transport 仅在 API/Platform。
- Credential UI 永不接收可回显密钥。

## 8. 数据流、调用流与依赖方向

```text
session selection -> conversation read
composer submit -> request workflow -> pending state -> response append
cancel -> request ID -> platform cancellation -> late result discard
profile edit -> explicit save -> credential action separate
```

## 9. 状态所有权与事务边界

- 会话目录、当前会话、草稿、pending request、profile editor、logs filters 各自独立 State。

## 10. 公共契约与兼容要求

- 切换页面/会话保留草稿。
- 普通问答纯文本。
- 取消只影响目标请求。
- 日志脱敏和防刷屏策略不变。

## 11. 风险与禁止事项

- 密钥不得进入 DOM snapshot、日志、错误正文或持久化草稿。
- 不得把 profile test 状态混入正式启用状态。

## 全阶段强制执行规则

1. 本阶段只允许修改本阶段明确列出的目标模块，不得夹带无关重命名、格式化、依赖升级或功能变化。
2. 模型保护区 `crates/model-api/`、`crates/model-p4/`、`crates/model-p7/` 以及关联参数、Profile、Schema、fixture、Golden Master 不得修改。
3. 任何原文件出现第二个独立职责时，必须把该职责模块升级为目录：原职责迁入具名文件，新职责进入新的具名文件；不得继续向原文件追加。
4. 不得使用 `old`、`new`、`legacy`、`copy`、`final`、`v2` 作为长期文件名或目录名。所谓旧职责和新职责必须使用真实业务语义命名。
5. 每条公共 Tauri 命令、DTO 字段、数据库格式、配置键、错误语义、日志等级和用户可观察行为默认保持兼容。
6. 每个业务状态只能有一个所有者；View 不拥有业务状态，API 不拥有页面状态，Repository 不拥有工作流状态。
7. 新旧实现只能在单个 Atomic Task 的受控切换窗口内短暂共存；任务结束前必须切换唯一入口并删除旧实现。
8. 不得新增生产依赖。确有必要时，必须单独提交依赖评估，不得混入业务任务。
9. 每个 Atomic Task 必须先通过最小验证，再运行阶段回归；硬性验证失败立即停止，不得进入下一任务。
10. 实际源码、配置、接口或行为发生变化时，同步更新根目录 `README.md`，只记录实际完成和实际验证结果。
11. 每个节点完成时必须创建 `docs/modular-rewrite/R15-ai-profiles-logs-ui/<task-record>.md` 并更新阶段 `README.md`；阶段完成时必须创建 `R15-stage-completion.md`。缺少记录不得标记为 `DONE`。

## 原计划阶段摘要（保留用于追溯）

## R15：AI Workspace、OpenAI Profiles 与 Logs UI 重写

### R15-01 AI Session Directory

实现 session-directory 的目录、搜索、选择和归档；与 conversation state 分离。

### R15-02 Conversation

实现 message list、滚动、空状态和只读历史；消息展示不得承担 composer 逻辑。

### R15-03 Composer

实现草稿、发送、编辑、键盘行为和输入持久化；不得包含请求 transport。

### R15-04 Pending Request

实现 pending-request 状态、加载、失败和重试；每个请求有明确 ID。

### R15-05 Request Cancellation

实现取消动作和迟到响应丢弃；取消不得误伤其他会话请求。

### R15-06 Context Picker

实现只读上下文选择和摘要；不得在普通聊天中启用正式 P4 schema、工具或隐式数据库写入。

### R15-07 OpenAI Profile Directory

实现配置目录、选择、启用状态和测试结果；不保存密钥明文。

### R15-08 OpenAI Profile Editor

把基础配置、协议、端点、模型名和超时设置拆成子模块；不要建立一个巨型 profile editor 文件。

### R15-09 API Example Parser

独立解析和预览；解析结果不得自动修改正式配置，必须经显式确认。

### R15-10 Credential Actions

写入、替换、清除和状态展示分别处理；敏感值不进入 DOM snapshot、日志或错误正文。

### R15-11 Profile Test

连接测试独立工作流，区分网络失败、认证失败、协议不兼容和取消。

### R15-12 Logs

逐目录实现 issue-directory、issue-detail、issue-export、issue-clear、runtime-log-summary。

### R15-13 Diagnostics Bridge

验证前端 trace 与后端 runtime log 的关联 ID、脱敏和防刷屏策略。

R15 验收：草稿切换保留、取消可靠、普通问答保持纯文本、密钥零泄漏、日志无敏感正文。
