# R4：Persistence 基础设施重写——独立执行任务书

> 文档编号：`R04`  
> 前置阶段：`R3`  
> 后续阶段：`R5`  
> 本文档是唯一执行依据之一；必须与 `00-总体架构与前23节.md` 同时适用。

## 1. 阶段目标

- 建立 PostgreSQL Adapter 的统一基础设施、错误、审计和映射规范。
- 让后续 Repository 按业务域独立实现 Ports。

## 2. 本阶段解决的实际问题

- 基础连接、错误、审计、Row 映射规则可能分散。
- 后续 Repository 若无统一规范会重复处理时间、UUID、JSON、enum 和 invalid state。

## 3. 前置输入与进入条件

- R3 Ports 已冻结。
- 迁移 0001-0046 指纹通过。

## 4. 明确范围

### 4.1 纳入范围

- PostgresStore、pool、migration runner、health、stats、error、audit、mapping primitives、adapter registration。

### 4.2 排除范围

- 具体业务 SQL。
- 迁移修改。

## 5. 当前实现来源与扫描重点

- `crates/persistence-postgres/src/lib.rs`。
- 现有 pool/migration/health/audit/hash/error 相关模块。

## 6. 目标目录总览

```text
crates/persistence-postgres/src/
  store/
  pool/
  migrations/
  health/
  statistics/
  error/
  audit/
  mapping/
  adapters/
  lib.rs
```

## 7. 目录与文件边界规则

- SQLx 只存在于 persistence-postgres。
- 通用 mapping 只处理基础标量，不做业务动态映射。
- 审计写入必须在业务事务边界内调用。

## 8. 数据流、调用流与依赖方向

```text
Application Port -> Postgres Adapter -> Query/Transaction -> Row -> Mapper -> Domain
write transaction -> business rows + audit row -> commit
```

## 9. 状态所有权与事务边界

- 连接池由 PostgresStore 唯一持有。
- 事务由具体 transaction 模块拥有，不跨 async task 泄漏。

## 10. 公共契约与兼容要求

- 不修改任何历史迁移。
- 连接配置、错误语义、health/stats 输出兼容。

## 11. 风险与禁止事项

- 不得建立万能 `mapper.rs` 或 `queries.rs`。
- 不得吞掉 SQLx 错误。

## 全阶段强制执行规则

1. 本阶段只允许修改本阶段明确列出的目标模块，不得夹带无关重命名、格式化、依赖升级或功能变化。
2. 模型保护区 `crates/model-api/`、`crates/model-p4/`、`crates/model-p7/` 以及关联参数、Profile、Schema、fixture、Golden Master 不得修改。
3. 任何原文件出现第二个独立职责时，必须把该职责模块升级为目录：原职责迁入具名文件，新职责进入新的具名文件；不得继续向原文件追加。
4. 不得使用 `old`、`new`、`legacy`、`copy`、`final`、`v2` 作为长期文件名或目录名。所谓旧职责和新职责必须使用真实业务语义命名。
5. 每条公共 Tauri 命令、DTO 字段、数据库格式、配置键、错误语义、日志等级和用户可观察行为默认保持兼容。
6. 每个业务状态只能有一个所有者；View 不拥有业务状态，API 不拥有页面状态，Repository 不拥有工作流状态。
7. 新旧实现只能在单个 Atomic Task 的受控切换窗口内短暂共存；任务结束前必须切换唯一入口并删除旧实现。
8. 不得新增生产依赖。确有必要时，必须单独提交依赖评估，不得混入业务任务。
9. 每个 Atomic Task 必须先通过最小验证，再运行阶段回归；硬性验证失败立即停止，不得进入下一任务。
10. 实际源码、配置、接口或行为发生变化时，同步更新根目录 `README.md`，只记录实际完成和实际验证结果。
11. 每个节点完成时必须创建 `docs/modular-rewrite/R04-persistence-foundation/<task-record>.md` 并更新阶段 `README.md`；阶段完成时必须创建 `R04-stage-completion.md`。缺少记录不得标记为 `DONE`。
