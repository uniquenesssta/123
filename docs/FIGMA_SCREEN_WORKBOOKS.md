## 4. 类别与批次身份

球队：`team-demo-2026-10.xlsx` / `T-DEMO-01`；球员：`player-demo-2026-10.xlsx` / `P-DEMO-01`；比赛：`match-demo-2026-10.xlsx` / `M-DEMO-01`。这三个独立通过场景都只显示1/3已预检，不凭空把其他类别标记为完成。

`Team Ready → Player Isolated → Team Ready` 是限定可交互路径：球员尚未预检、提交禁用，球队批次保留。其他多批次排列转入只读隔离说明，避免用一个Idle画面冒充任意状态持续性。通用入站不转移来源页面文件、模式或批次。

球队月度不是球队完整资料包。错误类型场景不给出可提交资格。预检数量与可提交数量、已写入数量不是同一指标；尚未取得结果不伪造为成功空数据。

## 5. 预检、模式与写入保护

`新增并更新` 与 `仅新增` 分开。仅新增重新预检使用 **T-DEMO-02**，新增2、更新0、已有两行跳过；独立提交确认和明细说明都使用T-DEMO-02，不复用T-DEMO-01。

空白默认保留已有值；`clear`是显式清空请求，仍须通过必填、类型和权限校验。未知年龄、概率、比分或评分不补为0。

冲突和格式错误是不同阻断。示例分别显示候选身份说明与字段错误；没有把“查看候选”或处理一项解释为其他错误也已解决。完整冲突写入控制器没有实现。

无变更、提交中、已导入、重复、文件变化、模式变化、结果未确认均禁提交。提交中同时禁更换文件、导入模式及导出。结果未确认保留批次，先核验、不自动重发。

已有预检状态的“选择文件”不会经同一个演示选择器回到旧批次Ready。16条相关路径改为重新预检说明，结果未确认路径进入核验说明；从尚未预检类别使用的3个演示选择器，明确只打开独立预检示例，不读取文件。

Imported保留原预检快照并标明是读回示例，不把旧新增/更新计数当成仍待提交。重复判定和幂等规则需要真实服务端支持；不以同文件名推断重复，也不宣称已验证后端实现。

导出中、导出失败和导出完成也独立呈现；导出不会产生导入预检资格。6个最终导出确认均不执行文件写入或覆盖现有文件。
