## 4. 本机可用性与读取

本机问题日志不依赖业务数据库。无数据库时仍可查看本机记录并打开导出/清空示意；Shell同步为未配置。数据库连接时list命令会扫描失败后台任务，因此刷新不仅是静态读取，也可能追加本机问题。

后台扫描失败可以形成问题D，同时本机列表仍可返回。列表可读不代表数据库健康。D在此作为追加说明展示，不声称覆盖任意记录排序控制器。

首次读取和读取失败显示“—”，不能显示0。成功读到空集合才显示0；空日志不是系统健康证明。刷新保留上次快照并明确标记，读取失败不能拿旧快照冒充新结果。

当前`load_entries`对文件读取/JSON解析失败会回退为空集合。设计中的未知/失败区别仍需源码实现，不能把视觉状态当作该缺口已修复。

## 5. 导出、技术详情与敏感信息

导出是当前保留集合的本机文本快照，不上传，不自动修复，也不是全部runtime trace。报告字段包含编号、来源、次数、首次/最近时间、操作及最近非空技术信息。友好描述只用于页面；报告示例保留空原始字段，不把友好兜底伪造成实际错误文本。

`Export Save`是原生保存位置选择的有限示意，不是新增强制业务确认，也没有实现文件选择器。最终保存按钮不写文件。保存成功、失败、取消位置选择及后续快照变化均是独立预置结果。当前列表变成3条/12次时，已导出报告仍为3条/11次，不能假装文件自动更新。

技术详情、HTML、SQL、堆栈和路径均为只读文本，不自动执行。当前源码只对PostgreSQL URL口令做定向脱敏，不能推断所有token、Authorization、个人信息及路径已完整处理。共享报告前仍需核对；本设计不包含实际凭据。

## 6. 清空与结果核验

清空本机问题集合不清空业务数据库、模型运行或独立运行追踪文件，也不修复原故障。当前实现先清空内存，再写入文件；持久化失败不保证内存与磁盘仍保持原状。

清空中保留操作前快照并禁重复操作；失败/结果未知显示待核验，3条/11次仅作此前快照说明，不作为当前可靠数量。不能自动重发清空。确认后集合变化另有禁用说明，但当前clear命令没有版本参数；运行时仍需绑定确认快照，防止静默删除确认后新增证据。

清空成功示例为0；随后扫描数据库中仍失败的任务，可重新创建B，从1次和新的首次时间开始。这是新的记录周期，不是自动恢复备份或恢复旧计数。
