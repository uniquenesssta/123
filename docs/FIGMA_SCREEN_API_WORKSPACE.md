## 4. 会话、请求与草稿

A=`CHAT-DEMO-A`，球队资料说明，关联TEAM-A；B=`CHAT-DEMO-B`，通用字段问答；C=`CHAT-DEMO-C`，历史文件处理；D=`CHAT-DEMO-D`，首轮完成后的新会话示例。所有编号、文字和时间都是设计数据，不是实际后端UUID。

已有会话锁定原API配置、问答类型和关联对象。原配置密钥不可用时保留身份和草稿，不自动改用其他配置。“密钥已保存”仅表示示例配置状态，不代表网络请求健康或密钥已验证。

REQ-A-01发送时，A显示待处理问题；历史预览仍展示已确认消息。可以进入B并保留B独立草稿，B消息区不出现A的问题。继续B对话时仍受A的全局发送锁约束，没有把“浏览另一个会话”当成可以并发发送。

A完成时仍停留B；回到A才看到A新增消息。A完成后的历史使用4条消息版本，不退回2条旧示例。读取B失败或等待时没有正文，不使用A占位；B成功入口保持未筛选的原历史，而不是擅自注入搜索关键词。

取消请求不等于取消终态，结果未知不自动重发。失败/取消场景保留A草稿与最近确认的历史；**不据此断言服务端尚未保存任何用户消息**，重试前仍需核验。NEW / REQ-NEW-01是临时请求身份，只有独立完成示例才呈现D。
