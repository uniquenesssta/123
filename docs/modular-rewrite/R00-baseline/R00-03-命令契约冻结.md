## 10. 实施过程中的关键决策

| 决策 | 采用方案 | 未采用方案 | 原因 |
|---|---|---|---|
| 命令唯一性 | Rust 定义和 handler 注册禁止重复；前端按命令集合校验，允许同一命令在不同调用路径出现 | 要求前端每个命令字符串只能出现一次 | 前端日志降级或多个 UI 入口可能合法复用同一命令 |
| 动态命令名 | 只允许中央 `invoke(command, args)` 包装器把参数传给 `tauriInvoke`，其他动态直接调用失败 | 允许任意动态命令字符串 | 任意动态命令无法被静态冻结和审计 |
| DTO 定位 | 契约记录前端签名文件、共享 DTO 文件及每个 Rust 定义文件 | 在 R0-03 复制完整类型文本进 JSON | 避免创建第二份类型真相并导致契约与源码双向漂移 |
| 注册顺序 | 冻结 `generate_handler!` 当前顺序并校验 | 只比较无序集合 | 顺序虽通常不改变语义，但冻结当前基线有助于审查无关改动 |
| 现有大文件 | 本节点只扫描和冻结，不拆分 `src/api/client.ts`、`src-tauri/src/lib.rs` 或 `commands.rs` | 在基线阶段提前重构 | R0-03 禁止跨入后续模块化重写范围 |
| 依赖引入 | 仅使用 Node 内置 `fs`、`path`、`crypto`、`url` | 新增 AST 或解析器依赖 | 不改变依赖和锁文件，并保持 Windows/CI 可执行 |
