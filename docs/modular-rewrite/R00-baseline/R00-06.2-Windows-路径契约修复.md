## 2. 目标

关闭 R0-06 与 R0-06.1 留下的两个 Windows 路径契约缺口：

1. 根目录 `验收平台.bat` 传入 `-LogDirectory .\logs`，而 `scripts/windows-acceptance.ps1` 未声明该参数。
2. Cargo 实际 release 输出到源码目录上级的 `.cargo-target\release`，旧验收器却在 `$SourceRoot\.cargo-target\release` 查找可执行文件。

本节点只修复验收工具路径解析，不修改业务行为、公共接口或数据结构。

## 3. 现状与可复现行为

### 日志参数不一致

根入口调用：

```text
powershell ... scripts\windows-acceptance.ps1 -Mode Full -LogDirectory .\logs
```

旧 PowerShell 参数列表没有 `LogDirectory`，因此根入口会在进入环境、数据库或运行时验收前因未知参数失败。

### Cargo release 路径不一致

`.cargo/config.toml` 与 `scripts/prepare-cargo-target.mjs` 的既有契约是：

```text
项目根目录\.cargo-target
```

旧验收器却固定读取：

```text
项目根目录\项目源码\.cargo-target\release
```

这与 Tauri 实际构建目录不一致。

## 6. 模块边界

```text
验收平台.bat
  └─ scripts/windows-acceptance.ps1
       ├─ Resolve-AcceptanceLogRoot
       ├─ Resolve-CargoTargetRoot
       └─ Find-AcceptanceReleaseExecutable
            └─ scripts/windows/acceptance-paths.psm1
```

- `windows-acceptance.ps1` 继续负责编排验收阶段。
- `acceptance-paths.psm1` 只负责路径解析和 release 文件定位。
- `verify-windows-path-contract.mjs` 只负责契约门禁，不执行构建或业务操作。

## 7. 路径语义

### 验收日志

- 未传 `LogDirectory`：默认写入 `$ProjectRoot\logs`。
- 传入绝对路径：直接规范化使用。
- 传入相对路径：相对于 `$ProjectRoot` 解析。

### 应用运行日志

应用 runtime JSONL 继续固定写入 `$ProjectRoot\logs`，不随验收报告输出目录变化。这样自定义验收证据目录不会改变桌面应用运行时契约。

### Cargo target

1. 优先读取 `$SourceRoot\.cargo\target-location.json` 中的绝对 `target_root`。
2. 登记文件不存在时，回退到 `$SourceRoot\..\.cargo-target`，与 `.cargo/config.toml` 保持一致。
3. release 查找只在解析后的 target 根目录下进行。
