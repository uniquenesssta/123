## 10. 实施过程中的关键决策

| 决策 | 采用方案 | 未采用方案 | 原因 |
|---|---|---|---|
| 公开仓库缺少真实模型资产时的保护方式 | 冻结公开模型边界并验证私有资产继续缺席 | 创建虚假的 P4/P7 参数、fixture 或 Golden Master 占位文件 | 源材料不支持这些资产存在，伪造会污染公开边界并改变事实 |
| 跨平台指纹 | 对 UTF-8 文本统一 CRLF/CR 为 LF，再计算 Git blob SHA-1 与派生 SHA-256 | 直接哈希工作树原始换行 | Windows `core.autocrlf` 会导致同一 Git 内容产生平台差异 |
| SHA-256 来源 | 每文件保存 `sha256('git-blob-sha1:' + git_blob_sha1)`，并对排序后的路径和文件指纹计算聚合 SHA-256 | 仅保存 GitHub blob SHA-1 | 同时保留 GitHub 可核对的对象身份和任务要求的 SHA-256 门禁 |
| 目录漂移 | 对 `model-api`、`model-stub`、`model_shell` 和 `contracts/model-*.json` 执行精确文件集合校验 | 只校验已知文件但允许新增旁路文件 | 防止新增未登记模型实现、参数或契约绕过单文件指纹 |
| 依赖引入 | 仅使用 Node 内置 `fs`、`path`、`crypto`、`url` | 新增 glob 或哈希生产依赖 | 保持 Windows/CI 可运行且不改变依赖和锁文件 |
