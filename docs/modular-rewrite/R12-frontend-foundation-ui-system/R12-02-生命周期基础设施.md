## 范围与实际职责

R12-01的启动句柄已有部分清理行为，但仍有重复生命周期状态机、启动与销毁重叠后继续启动后续模块、未统一持有的UI定时器、过期解析结果与工作区恢复帧问题。现收敛到以下唯一实现；不是把Feature状态移入全局store。

| 文件 | 职责与实际调用方 |
|---|---|
| `app/lifecycle/mountHandle.ts` | 一次启动/停止/销毁；同步中止回调后等待已开始启动，部分失败也仅清理一次；重入时先发布destroy promise |
| `app/lifecycle/disposable.ts` | 独立资源按登记逆序释放；一个释放失败不跳过其他资源；保留全部原始错误 |
| `app/lifecycle/eventScope.ts` | AbortSignal事件边界、显式事件注销、timeout/interval/animation frame登记与取消；已排队回调也检查归属 |
| `app/lifecycle/asyncScope.ts` | 每所有者一个latest-wins通道，请求id/signal/commit/finish；过期成功与失败均不覆盖当前状态；当前错误不吞掉 |
| `app/lifecycle/lifecycleError.ts` | 内部生命周期结束错误和清理错误展开；不改公共Tauri错误/DTO |
| `app/lifecycle/index.ts` | 仅具名re-export |
| `bootstrap/applicationHandle.ts` | 仍唯一拥有应用模块登记和顺序；委托MountHandle与DisposableScope，移除原第二套start/destroy状态机及清理循环 |
| `bootstrap/registerApplicationModules.ts` | 原延迟加载/真实runtime保留；stop同步传递，加载期间已停止则不再启动runtime |
| `main.ts` | 真实浏览器模块使用MountHandle/EventScope；启动摘要与API示例解析分别拥有AsyncScope；停止时使原导航/阵容序列失效 |
| `app/viewState.ts` | 持久业务快照仍由原WorkspaceStateStore拥有；只接入生命周期：停止恢复帧、取消延迟保存、丢弃迟到初始化、最终flush一次 |

`stop()`仅同步使回调失效，`destroy()`随后等待已开始启动并完成资源释放。不能把前端AbortSignal当成服务端事务已取消的证明；没有新增真实API取消、后台任务取消或事务回滚承诺。其余Feature请求、路由、会话和工作区业务继续由后续节点完善。

启动失败保持原错误优先，清理失败时AggregateError首项仍是启动错误；既有“应用生命周期已结束”“应用模块启动失败/销毁失败”文案保持。销毁过程中不再启动后续模块，销毁重入共享同一promise，清理失败仍清空模块引用。浏览器停止后不再render/toast，原全局监听器仍绑定唯一scope.signal；工作区最终capture/flush及数据格式保持。
