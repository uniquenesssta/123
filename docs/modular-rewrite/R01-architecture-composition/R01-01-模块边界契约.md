## 2. 原始问题与本节点目标

- 原始问题：现有边界分散在 Cargo 清单、前端入口、Tauri 命令、应用服务和人工说明中，缺少一份可供后续脚本验证的模块依赖契约；共享状态虽有实际所有者，但没有统一、机器可读的唯一所有权声明。
- 本节点目标：建立模块依赖和状态所有权两份权威 JSON 契约，为 R1-02 的自动边界门禁以及 R1-03 至 R1-05 的组合根拆分提供固定输入。
- 明确不处理：不迁移 Feature、Domain、Repository 或命令实现，不拆分 `src/main.ts`、`src-tauri/src/lib.rs`、`src-tauri/src/commands.rs` 或 `crates/application/src/lib.rs`，不改变公共接口、运行行为、配置、依赖、数据库、模型或 UI。

## 7. 边界与所有权决策

### 7.1 前端

- `src/main.ts` 仍是当前浏览器组合和页面编排所有者，仅标记为 R1-03 的待迁移入口。
- `src/api/client.ts` 是 Tauri transport 唯一所有者；页面、组件和 `src/app` 不得直接导入 `@tauri-apps/api/core`。
- 18 个现有页面文件分别登记为当前 Feature owner；目标 `src/features/<feature>` 只表示后续迁移位置，本节点不创建空壳或复制实现。
- `src/app/viewState.ts`、`src/app/navigation.ts` 和 `src/app/modal.ts` 分别继续拥有工作区文档、导航竞态状态和详情面板历史。

### 7.2 Rust

- Cargo 清单中的当前 workspace 依赖作为允许边，未虚构不存在的依赖倒置层。
- `football-domain` 保持零 workspace 内部依赖。
- `PredictionModel`、`OpenAiTransport`、`GatewayAttemptSink`、`ApiKeyProvider` 作为现有端口登记。
- SQLx/PostgreSQL pool 仅由 `football-persistence-postgres` 所有；Tauri command 模块不得复制数据库连接或模型注册状态。
- `ApplicationService` 继续唯一持有 `ModelRegistry`、活动数据库与 P4 worker guard；R1-05 完成前不改变。

### 7.3 Tauri 和命令

- `src-tauri/src/lib.rs::run` 仍是当前桌面组合入口。
- `src-tauri/src/commands.rs::AppState` 仍是桌面共享引用容器。
- 171 个命令不在新契约中复制第二份名称清单；`architecture/command-contract.json` 保持唯一权威来源，新契约只登记数量、注册所有者和 15 个命令组。
- 命令名称、参数、返回类型、注册顺序、启动行为和窗口行为均未修改。

## 8. 状态所有权摘要

契约覆盖：浏览器生命周期、导航、工作区、弹窗历史和本地偏好；Application 模型注册表、活动数据库和 P4 worker；Persistence SQLx pool；Tauri AppState、配置路径、问题日志、运行日志、OpenAI profiles、工作区状态和 API 请求取消表；Windows Credential Manager 中的 API key。

每一状态 ID 只有一个当前 owner。计划迁移目标在对应 Atomic Task 完成前不得被视为新所有者。

- 前端页面、导航、状态恢复、弹窗、日志和 API 调用行为保持不变。

- 数据格式、持久化结构、数据库迁移、历史数据、配置、错误语义和日志等级保持不变。
