## 1. 实际问题

R2 后续任务需要按业务语义移动 365 个现有领域类型，但此前没有一份可机器复算的权威清单来回答以下问题：

- 类型当前定义位置和计划目标目录；
- Serde 名称、属性、默认值与 optional 语义；
- PostgreSQL 映射与上下游调用位置；
- 哪些类型属于公共兼容出口；
- 各类型应由 R2-02 至 R2-07 中哪个 Atomic Task 负责。

在缺少该基线时直接迁移，存在漏类型、重复类型、隐式 Serde 漂移、数据库映射断裂和 glob re-export 掩盖无归属类型的风险。

## 2. 完成内容

- 建立确定性 Domain 类型发现器，只识别 `crates/domain/src` 模块顶层 `struct`、`enum` 和 `type` 声明，排除测试模块和 `impl` 内关联类型。
- 建立 Rust 调用链扫描器，扫描 Domain 内部调用、workspace 外部调用和 PostgreSQL 适配器映射。
- 建立独立目标模块策略，将类型映射到 17 个业务目标模块和 R2-02 至 R2-07 的明确责任节点。
- 建立清单文档生成器和漂移验证器；任何类型、声明、调用链、目标策略或数据库映射变化都会导致门禁失败。
- 生成 `architecture/domain-type-inventory.json`，作为 R2 类型迁移的机器权威清单。
- 建立 `crates/domain/tests/serde_contracts/`，覆盖历史 JSON 往返、枚举线值、默认值和 optional 语义。
- 将清单漂移验证接入 `npm run verify:architecture` 和 `scripts/verify-frontend.mjs`。
- 未迁移、复制、重命名或修改任何 `crates/domain/src` 生产类型。

## 10. 实施中发现并关闭的问题

- 初始临时 workflow 的 YAML 条件包含未引用冒号，解析失败；未执行任何生成或源码操作，随后修正调度语法。
- 大块压缩载荷发生字节破坏；未生成基线，随后改为逐文件 Git Blob 写入并校验。
- 初始扫描器误将 `impl FromStr` 中的关联类型 `type Err` 识别为领域类型；收紧为仅识别模块顶层声明。
- 枚举测试辅助函数错误要求所有枚举实现 `PartialEq`；改为比较序列化线值往返，不修改生产枚举契约。
- Rust 全工作区首次只因新增测试未符合 rustfmt 排版失败；按 Rust 1.88 rustfmt 精确输出修正后完整复跑通过。

上述失败均发生在硬门禁内，失败版本没有生成清单基线或被描述为通过。
